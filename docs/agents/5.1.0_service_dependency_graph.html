5.1.0_service_dependency_graph

Which layers provide AstroParams and Ephemeris, and which modules require them. Runtime.MainLayer ships both services by default.

  • Solid arrows are the shipped wiring; dashed arrows are alternatives or decorators.
  • Runtime.MainLayer is Layer.mergeAll(AstroParamsSubgraph, EphemerisSubgraph), i.e. DefaultAstroParams plus SwissephCachedLayer, so providing it satisfies both services.
  • Swisseph.SwissephCachedLayer is withPositionCache().pipe(Layer.provide(SwissephLayer)). It memoizes calculatePosition per (julianDay, body, ayanamsa) for 10 minutes, never caches failures, and passes calculateHouses and dateToJulianDay straight through.
  • withPositionCache(options) decorates any Ephemeris layer, so it requires Ephemeris and provides Ephemeris.
  • DefaultAstroParams pins ayanamsa KrishnamurtiVP291 and house system Placidus. layerConfig(config) reads the same options through Effect Config, so it needs an ambient ConfigProvider.
  • Dasha, Jaimini and SAV need no services. They are pure functions over the Placements that Chart.generate produces.
  • Transit.findTransits and Transit.searchRawHits sample through sampleAt, so they inherit its Ephemeris requirement.
  • examples/runtime.ts merges BunServices.layer with the uncached Swisseph.SwissephLayer, so the examples run without the position cache.
